# 12-1. 부록: 프롬프트 모음과 체크리스트

이 부록은 매일 쓰는 문장을 모은 것입니다. 그대로 복사해서 보내면 됩니다. 괄호 안의 값만 내 상황에 맞게 바꾸십시오.

## 1. 처음 시작할 때

```
내 티스토리 블로그에 매일 글을 자동으로 올리고 싶어.
블로그 주소는 (주소)이고, 주제는 (주제)야.
먼저 계정과 블로그 상태를 점검하고, 자동 발행에 필요한 것들을 순서대로 알려 줘.
```

```
내 블로그 글 규격표를 만들어 줘.
분량, 소제목, 문단, 이미지, 태그, 링크 항목으로 표를 만들고 추천 값과 이유를 붙여 줘.
내가 값을 고르면 그걸 최종 규격으로 저장해 줘.
```

## 2. 발행을 맡길 때

```
(블로그 이름)에 (편수)편을 발행해 줘.
첫 편은 지금 공개, 나머지는 (간격)분 간격으로 예약.
발행 전에 규격을 검수하고, 끝나면 링크와 표로 보고해 줘.
```

```
매일 (시각)에 자동으로 돌게 등록해 줘.
실패한 편은 저녁에 한 번 더 시도하고, 결과는 블로그별로 나눠서 보고해 줘.
```

## 3. 문제가 생겼을 때

```
발행은 됐는데 본문이 비어 있어. 다시 발행해 주고, 발행 뒤에 본문 길이와 공개 상태를 확인해서 알려 줘.
```

```
같은 글이 두 번 올라갔어. 중복 글을 찾아서 하나만 남기고, 다시 실행할 때 중복 확인을 먼저 하도록 바꿔 줘.
```

```
예약이 안 걸리고 바로 공개됐어. 예약 시각이 과거인지 확인하고, 앞으로는 예약 시각을 현재보다 최소 40분 뒤로 잡아 줘.
```

```
사이트가 안 열려. 트래픽 초과인지 먼저 확인하고, 원인과 복구 시각을 알려 줘. 복구될 때까지 발행은 멈춰 줘.
```

## 4. 점검을 받을 때

```
지난 한 주를 정리해서 보고해 줘.
발행 편수, 실패 편수, 색인 수 변화, 유입이 많은 글 다섯 개, 광고 수익, 제휴 클릭, 반복되는 실패 원인.
다음 주에 바꿀 것 두 가지만 추천해 줘.
```

```
발행 전 검수를 맡겨 줘. 규격표로 원고를 검사하고 어긋난 항목만 표로 보여 줘. 어긋나면 발행하지 말고 고칠 부분을 알려 줘.
```

## 5. 수익화 문장

```
애드센스 신청 전에 사이트를 점검해 줘. 글 수, 필수 페이지, 사이트 상태를 확인하고 부족한 항목을 알려 줘.
```

```
색인이 안 된 글을 정리해 줘. 새 글과 필수 페이지부터 순서를 매기고, 하루 한도 안에서 색인 생성 요청을 눌러 줘. 한도에 걸리면 멈추고 남은 목록을 남겨 줘.
```

```
매일 밤 11시 30분에 색인 요청 루틴이 돌게 등록해 줘. 속성당 한도까지, 초과하면 바로 멈추고, 다음 날 아침에 결과 표로 보고해 줘.
```

```
제휴 링크를 글에 붙여 줘. 글 하나당 하나, 다른 제휴와 번갈아. 고지 문구는 모든 글에 자동으로 들어가게 해 줘.
```

## 6. 하지 말아야 할 것을 알려 둘 때

```
앞으로 이런 일은 하지 마.
- 계정을 새로 만들거나 비밀번호를 바꾸는 일
- 결제를 진행하는 일
- 글을 삭제하는 일
필요하면 먼저 나에게 물어봐.
```

이 문장은 처음 한 번만 말해 두면 됩니다. 자동화를 오래 돌릴수록 이런 경계가 중요해집니다.

## 규격표 체크리스트

```text
[ ] 분량 3,000~5,000자
[ ] 소제목 3~5개
[ ] 문단 2~4문장
[ ] 이미지 3~7장, 대표이미지 1장
[ ] 태그 10개
[ ] 카테고리 고정
[ ] 제휴 링크 1개, 고지 문구 포함
[ ] 금지 표현 없음
```

## 발행 전 체크리스트

```text
[ ] 규격 검수 통과
[ ] 제목과 본문 일치
[ ] 공개 범위가 공개
[ ] 대표이미지 업로드 완료
[ ] 태그 10개, 철자 확인
[ ] 예약 시각이 현재보다 뒤
```

## 주간 점검표

```text
[ ] 발행 성공률
[ ] 검수 실패 건수
[ ] 색인 요청 건수와 색인 증가
[ ] 광고 노출과 클릭
[ ] 제휴 클릭
[ ] 저장 용량과 트래픽
```

## 사고 대응 순서

```text
1. 사이트가 열리는지 확인한다
2. 발행을 멈춘다
3. 오늘 기록을 남긴다
4. 원인을 하나씩 확인한다
5. 다시 실행하고 중복이 없는지 본다
```

## 마지막으로 남기는 표

| 남겨 둘 것 | 역할 |
| --- | --- |
| 규격표 | 매일 같은 모양을 만드는 기준 |
| 검수 문장 | 발행 전에 어긋남을 잡는 절차 |
| 발행 기록 | 실패한 편을 이어서 처리하는 근거 |
| 주간 보고 | 무엇을 바꿀지 정하는 재료 |

이 네 가지가 있으면 블로그는 사람이 없어도 멈추지 않습니다. 도구의 이름이나 파일 형식은 달라져도 이 네 가지는 그대로 남습니다.
