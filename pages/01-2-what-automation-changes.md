# 01-2. 자동화가 줄이는 것과 줄이지 못하는 것

자동화를 붙이기 전에 기대치를 정확히 맞춰 두는 편이 좋습니다. 기대가 어긋나면 첫 주에 실망하고 절차를 버리게 됩니다.

| 구분 | 자동화가 줄이는 것 | 자동화가 줄이지 못하는 것 |
| --- | --- | --- |
| 주제 | 후보 목록 만들기, 중복 확인 | 무엇이 독자에게 통할지 판단 |
| 원고 | 초안 작성, 규격 맞추기 | 사실 확인, 경험에서 나오는 문장 |
| 발행 | 입력, 예약, 반복 클릭 | 발행 버튼을 누를지 결정하는 일 |
| 검색 | 등록, 사이트맵 제출 | 어떤 키워드로 이길지 선택 |
| 수익 | 지표 수집, 이상 탐지 | 광고 단가와 정책 판단 |

## 사람이 남겨야 하는 세 가지

1. 주제의 방향. 어떤 독자를 상대로 할지 정하는 일은 자동화가 대신할 수 없습니다. 이 결정이 흔들리면 글의 주제가 매일 달라지고, 검색엔진은 그 블로그를 하나의 주제로 인식하지 못합니다.
2. 사실 확인. 잘못된 정보를 하루에 열 편씩 발행하면 바로잡는 비용도 열 배가 됩니다. 확인이 필요한 주제는 발행 전에 사람이 읽습니다.
3. 되돌리기 어려운 조작. 계정 연결, 결제, 사이트 삭제, 정책 동의는 사람이 직접 합니다.

## 자동화에 맡겨도 되는 것

- 이미 정한 규격에 맞춰 원고의 형식을 갖추는 일
- 같은 절차를 반복하는 입력 작업
- 결과를 모아 표로 만드는 일
- 정해진 조건을 벗어났을 때 멈추는 일

마지막 항목이 가장 중요합니다. 잘 만든 자동화는 잘 돌아가는 자동화가 아니라, 이상할 때 멈추는 자동화입니다. 태그가 열 개가 아니면 발행하지 않고, 사이트가 503을 내면 아무것도 만들지 않고 종료합니다. 이 규칙이 없으면 잘못된 글이 예약 시각마다 하나씩 올라갑니다.

## 비용도 계산에 넣는다

자동화에는 눈에 보이지 않는 비용이 붙습니다. 호스팅 트래픽, 이미지 저장 공간, 도메인 갱신, 그리고 사람이 로그를 읽는 시간입니다. 하루 마흔 편을 발행하는 구성은 화려해 보이지만, 저가형 호스팅에서 돌리면 이미지 몇 장에 사이트가 닫힙니다. 09장에서 실제로 겪은 사고를 다룹니다. 처음에는 하루 열 편이면 충분합니다.
