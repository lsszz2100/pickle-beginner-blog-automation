# 03-1. 규격이 먼저인 이유

## 규격이 없으면 생기는 일

규격 없이 자동 발행을 돌려 본 실제 기록입니다.

| 일어난 일 | 원인 |
| --- | --- |
| 발행은 되는데 글이 비어 있음 | 본문 주입 방식이 저장되지 않음 |
| 태그가 7개로 발행됨 | 목록에서 일부가 중복으로 걸러짐 |
| 같은 주제가 이틀 연속 올라감 | 발행 이력을 확인하지 않음 |
| 대표이미지가 깨져 보임 | 확장자만 png이고 실제로는 웹 문서였음 |
| 예약이 거부됨 | 현재 시각보다 20분 뒤로 걸었음 |

다섯 가지 모두 규격과 검사로 막을 수 있었습니다. 규격은 글을 잘 쓰기 위한 것이 아니라, 이런 사고를 사전에 막기 위한 것입니다.

## 규격을 정하는 순서

1. 이미 잘 되는 글 하나를 고릅니다. 자기 블로그에서 반응이 있었던 글, 또는 참고하는 블로그의 글 하나입니다.
2. 그 글의 구조를 숫자로 셉니다. 문단 수, 섹션 수, 이미지 수, 글자 수, 소제목 길이.
3. 셈한 값을 조금 넓혀 범위로 만듭니다. 예를 들어 4,200자였으면 3,000~5,000자로 잡습니다.
4. 범위를 벗어나면 발행하지 않도록 검사를 붙입니다.

## 범위를 넓게 잡는 이유

정확한 한 값(예: 4,200자)으로 고정하면 원고가 계속 탈락합니다. 인공지능이 만든 원고는 같은 지시에도 글자 수가 10~20퍼센트 흔들립니다. 범위를 넓히고, 하한만 단단히 지키는 편이 안정적입니다.

이 책의 하한은 3,000자입니다. 이보다 짧으면 검색엔진이 얕은 문서로 판단하고, 광고가 붙을 자리도 부족합니다. 상한 5,000자는 읽는 사람의 집중 시간과 이미지 용량을 고려한 값입니다.

## 규격은 블로그마다 다르게 둘 수 있다

티스토리 세 곳과 워드프레스 한 곳에 같은 규격을 쓰지 않아도 됩니다. 다만 규격이 다르면 검수 스크립트도 블로그별로 값이 달라집니다. 관리 부담이 늘어나므로, 처음에는 한 가지 규격으로 통일하고 필요할 때 나누는 편이 좋습니다.

## 규격표를 어디에 두는가

규격표는 사람이 읽는 문서로도, 스크립트가 읽는 값으로도 존재해야 합니다. 가장 단순한 방법은 두 곳에 같은 숫자를 적고, 바꿀 때 함께 고치는 것입니다. 실수로 어긋나는 것이 싫다면 아래처럼 설정 파일 하나를 두고 문서는 그것을 옮겨 적습니다.

```json
{
  "min_chars": 3000,
  "max_chars": 5000,
  "min_images": 3,
  "max_images": 7,
  "tags": 10,
  "min_sections": 5,
  "max_sections": 7
}
```

이 파일 하나가 앞으로 모든 장에서 기준이 됩니다.
