# 03-1. 규격이 먼저인 이유

## 이 절에서 하는 일

규격표를 만들기 전에, 규격이 없을 때 무엇이 무너지는지 확인합니다. 이 절은 짧습니다. 읽고 나면 왜 다음 절부터 숫자를 정하는지 이해됩니다.

## 규격이 없을 때 생기는 일

| 증상 | 원인 | 결과 |
| --- | --- | --- |
| 어떤 글은 목록에서 제목만 보임 | 요약 문장이 없음 | 클릭률이 떨어집니다 |
| 같은 블로그인데 글마다 모양이 다름 | 문단 계층이 제각각 | 체류 시간이 줄어듭니다 |
| 태그가 3개인 글과 12개인 글이 섞임 | 태그 규칙이 없음 | 검색엔진이 주제를 못 잡습니다 |
| 대표이미지가 깨져 있음 | 이미지 출처 규칙이 없음 | 목록과 공유 화면이 비어 보입니다 |

네 가지 모두 글을 쓰는 사람이 매번 판단해서 생깁니다. 판단을 규격으로 바꾸면 같은 문제가 반복되지 않습니다.

## 이렇게 말하면 됩니다

규격표를 처음 만들 때는 피클에게 기준을 물어보게 하면서 만드는 편이 좋습니다.

```
내 블로그 글 규격표를 만들고 싶어.
정해야 할 항목을 먼저 보여주고, 각 항목에 추천 값과 이유를 붙여서 표로 만들어 줘.
내가 값을 고르면 그걸 최종 규격으로 저장해 줘.
```

## 피클이 되묻는 것

| 피클의 질문 | 내가 고르는 답 |
| --- | --- |
| 하루에 몇 편을 발행할까요 | 1편, 3편, 10편 중 선택 |
| 한 편의 분량은 몇 자로 할까요 | 2,000~3,000자 또는 3,000~5,000자 |
| 이미지는 몇 장이 적당할까요 | 3~7장 사이에서 선택 |

## 규격표의 기본 골격

| 항목 | 값의 예 | 정하는 요령 |
| --- | --- | --- |
| 분량 | 3,000~5,000자 | 검색 상위 글의 평균보다 조금 길게 |
| 소제목 | 3~5개 | 독자가 훑어볼 수 있는 단위 |
| 문단 | 2~4문장 | 한 문단이 길면 모바일에서 읽기 어렵습니다 |
| 이미지 | 3~7장, 대표이미지 1장 | 글자만 있는 글보다 체류 시간이 깁니다 |
| 태그 | 10개 | 주제어와 연관 검색어를 섞습니다 |
| 링크 | 제휴 링크 1개 | 글당 하나만, 고지 문구와 함께 |
| 마무리 | 확인 문장 1~2개 | 독자가 다음 행동을 알 수 있게 |

값은 블로그마다 달라도 됩니다. 중요한 것은 한 블로그 안에서 값이 고정되는 것입니다.

## 규격을 정한 뒤에 하는 일

규격표를 만들었으면 다음 문장으로 시험합니다.

```
방금 정한 규격으로 샘플 글 한 편만 써 줘. 발행은 하지 말고 본문만 보여줘. 내가 보고 고칠 점을 말할게.
```

샘플 한 편을 보고 나서 숫자를 조정합니다. 이 과정을 두세 번 반복하면 규격이 손에 익습니다. 그 뒤부터는 매일 발행을 맡겨도 결과물이 흔들리지 않습니다.

## 잘 안 될 때는 이렇게 말합니다

- "규격표 항목이 너무 많아."라고 하면 꼭 필요한 다섯 개만 남기자고 제안합니다.
- "샘플 글이 너무 딱딱해."라고 하면 문체 규칙(존댓말, 짧은 문장, 예시 위주)을 규격에 추가합니다.
- "블로그마다 규격을 다르게 하고 싶어."라고 하면 블로그별 규격표를 따로 만들어 줍니다.
