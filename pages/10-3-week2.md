# 10-3. 2주차: 발행 자동화

## 목표

사람이 개입하지 않아도 하루 열 편이 올라가고, 실패하면 다음 회차에 이어서 처리되는 상태.

## 8일차: 원고 생성 절차 만들기

```text
[ ] 주제 후보 30개를 파일로 정리
[ ] 원고 한 편을 생성해 규격에 맞추기
[ ] 검수 스크립트로 통과 확인
[ ] 통과할 때까지 규격과 지시문 다듬기
```text

원고 생성은 한 편으로 시작합니다. 열 편을 한 번에 만들면, 규격이 잘못된 상태로 열 편이 쌓입니다. 한 편이 통과하면 다섯 편으로 늘립니다.

## 9일차: 티스토리 자동 발행

```text
[ ] 04-2의 절차를 그대로 한 번 수행
[ ] 걸린 시간 기록
[ ] 실패한 단계 기록
[ ] 예약 발행으로 두 번째 편 걸기
```text

첫날은 자동화하지 않고 손으로 절차를 따라갑니다. 어디서 시간이 걸리는지 알아야 자동화할 부분이 보입니다. 대개 붙여넣기와 대표이미지 업로드에서 시간이 걸립니다.

## 10일차: 워드프레스 자동 발행

```text
[ ] 애플리케이션 비밀번호 발급
[ ] publish_batch.py 실행 (--dry-run)
[ ] 실제 발행 1편
[ ] 예약 발행 2편
[ ] 발행 결과를 API로 재조회
```text

## 11일차: 예약 간격과 상태 파일

```text
[ ] 예약 간격 계산 코드 작성
[ ] 블로그별 마지막 시각 저장
[ ] 하루 열 편 배치 실행
[ ] 다음 날 예약 시각 충돌 확인
```text

## 12일차: 첫 전체 실행

```text
[ ] 티스토리 3곳 × 10편
[ ] 워드프레스 10편
[ ] RSS로 결과 확인
[ ] 실패 로그 확인
```text

이날은 실패해도 괜찮습니다. 목적은 성공이 아니라 실패 지점을 찾는 것입니다. 로그를 보고 3주차에 고칩니다.

## 13일차: 실패 수정

| 로그 | 조치 |
| --- | --- |
| 이미지 부족 | 생성 규칙에 최소 3장 명시 |
| 태그 9개 | 중복 태그 제거 |
| 예약 거부 | 현재+40분 기준으로 재계산 |
| 응답이 JSON 아님 | 사이트 상태 확인 후 재시도 |

## 14일차: 점검과 기록

```text
[ ] 성공률 계산
[ ] 걸린 시간 측정
[ ] 다음 주 계획 수정
```text

## 2주차 체크

| 확인 | 기준 |
| --- | --- |
| 하루 발행 | 티스토리 30편 이상 |
| 성공률 | 80퍼센트 이상 |
| 실패 처리 | 상태 파일에 남음 |
| 재실행 | 중복 없이 됨 |

## 자주 막히는 곳

2주차에 가장 많이 막히는 지점은 티스토리 붙여넣기입니다. 포커스 문제로 붙여넣기가 사라지면, 그 회차는 통째로 실패합니다. 이때 절차를 줄이지 말고 7단계(소스 영역 클릭)를 다시 확인하십시오. 이 한 단계를 빼면 열 번 중 세 번은 실패합니다.

두 번째는 워드프레스 응답입니다. 상태 코드 200인데 본문이 HTML인 경우가 있습니다. 이때 발행 스크립트가 성공으로 기록하면, 실제로는 아무 글도 만들어지지 않은 상태가 됩니다. 응답 본문 형식 확인을 반드시 넣으십시오.
