# 07-5. 색인이 애드센스 승인과 이어지는 지점

## 이 절에서 하는 일

블로그에 글을 많이 올리면 애드센스가 붙는다고 생각하기 쉽습니다. 실제로는 글 수와 승인 사이에 한 단계가 더 있습니다. 그 글이 구글 검색에 색인되어, 검색 로봇과 방문자가 실제로 닿는 상태가 되는 일입니다. 이 절에서는 색인과 애드센스가 어디에서 이어지고 어디에서는 이어지지 않는지를 구분합니다.

## 먼저 정확히 해 둘 것

애드센스 도움말의 사이트 승인 안내에 "구글 검색에 색인되었는가"는 조건으로 적혀 있지 않습니다. 심사에서 보는 것은 콘텐츠가 직접 쓴 것이고 읽을 만한지, 메뉴와 링크로 글이 이어지는지, 정책에 어긋나지 않는지, 구글의 크롤러가 사이트를 읽을 수 있는지입니다. 그래서 색인이 잔뜩 되어 있어도 내용이 얕으면 승인은 나지 않습니다.

그런데도 색인을 먼저 보라고 하는 이유가 있습니다. 승인에서 막히는 사이트를 보면 두 가지 중 하나인 경우가 많습니다. 글이 검색에 하나도 없거나, 크롤러가 사이트를 읽지 못하거나. 둘 다 색인 화면에서 먼저 드러납니다. 색인은 승인 조건이 아니라, 승인이 붙을 만한 사이트인지 확인되는 창구입니다.

## 색인이 승인과 이어지는 네 지점

| 지점 | 색인이 없을 때 | 색인이 있을 때 |
| --- | --- | --- |
| 크롤러가 읽는가 | 읽지 못한 페이지는 심사에서도 보이지 않는다 | 읽힌 페이지가 심사 자료가 된다 |
| 방문이 있는 페이지인가 | 코드를 붙여도 연결 확인이 늦어진다 | 검색 유입이 연결 확인을 앞당긴다 |
| 광고가 보일 자리가 있는가 | 승인돼도 노출이 없다 | 노출과 클릭이 생긴다 |
| 콘텐츠가 쓸 만한가 | 색인이 안 되는 원인과 판정 사유가 겹친다 | 사유가 줄면 판정도 줄어든다 |

세 번째 줄은 승인 뒤의 이야기입니다. 승인 전에 보는 것은 첫 줄과 네 번째 줄입니다.

## 색인이 0인 채로 기다리는 흐름

1. 글을 30편 발행합니다.
2. 사이트맵을 제출하고 마음이 놓입니다.
3. 서치콘솔의 페이지 보고서는 열어 보지 않습니다.
4. 애드센스를 신청합니다.
5. "가치가 낮은 콘텐츠" 또는 "사이트에 연결할 수 없음"이 나옵니다.
6. 글이 부족한가 싶어 더 씁니다.

이 흐름에서 빠진 것은 3번입니다. 사이트맵을 제출한 것과 그 주소가 색인된 것은 다른 일입니다. 사이트맵은 "이런 주소가 있습니다"라고 알리는 목록이고, 색인은 구글이 그 주소를 읽고 검색에 넣기로 한 결과입니다.

## 무엇을 보면 되는가

| 확인 | 어디서 | 정상으로 보이는 모습 |
| --- | --- | --- |
| 색인된 페이지 수 | 서치콘솔 > 색인 생성 > 페이지 | 발행한 글 수에 가까워지고 있음 |
| 색인 생성 안 됨 사유 | 같은 화면의 아래쪽 | 사유별 개수가 줄어듦 |
| 사이트맵 마지막 읽은 날짜 | 서치콘솔 > 사이트맵 | 최근 날짜로 갱신됨 |
| 사이트 접근 | URL 검사 | URL이 Google에 등록됨 |
| 애드센스 사이트 상태 | 애드센스 > 사이트 | 준비 중에서 검토 중, 준비됨으로 |

숫자는 발행량보다 늦게 움직입니다. 오늘 쓴 글이 오늘 색인되지 않는 것이 정상입니다.

## 이렇게 말하면 됩니다

```
내 블로그 세 곳의 색인 상태와 애드센스 준비 상태를 같이 봐 줘.
- 속성별로 색인된 페이지 수와, 색인 생성 안 됨 사유 상위 세 개
- 사이트맵이 마지막으로 읽힌 날짜
- 애드센스 사이트 상태(준비 중, 검토 중, 준비됨)
- 색인이 막힌 원인 중 내가 고칠 수 있는 것과 고치는 순서
글을 더 쓰는 것보다 먼저 할 일이 있으면 그것부터 알려 줘.
```

## 피클이 되묻는 것

| 피클의 질문 | 내가 고르는 답 |
| --- | --- |
| 어느 블로그부터 볼까요 | 애드센스를 신청한 곳부터 |
| 사유를 전부 볼까요 | 상위 세 개만, 나머지는 개수만 |
| 신청은 언제 할까요 | 필수 페이지가 색인되고 새 글이 며칠 안에 색인되기 시작한 뒤 |
| 글 발행은 계속할까요 | 계속하되 하루 편수를 한도 안으로 줄임 |

## 내가 직접 하는 일

1. 구글 계정 로그인이 필요하면 보안 로그인 카드에 입력하고, 2단계 인증 알림을 승인합니다.
2. 애드센스 심사 요청 버튼은 직접 누릅니다. 신청은 되돌리기 어려운 일이라 맡기지 않습니다.
3. 결과 화면을 열어 상태 문구를 확인합니다.

## 확인한 뒤의 판단

- 색인이 거의 없고 사유가 "발견됨 - 현재 색인이 생성되지 않음"에 몰려 있으면, 요청보다 사이트맵과 내부 링크를 먼저 손봅니다.
- "크롤링됨 - 현재 색인이 생성되지 않음"이 많으면, 내용이 비슷하거나 얕다는 뜻입니다. 이 사유는 색인 요청을 아무리 눌러도 줄지 않으므로 글을 고칩니다.
- 필수 페이지만 색인되어 있으면, 발행한 글이 검색에 닿지 않은 상태입니다. 07-6의 순서로 요청합니다.
- 사유가 "noindex 태그에 의해 제외됨"이나 "robots.txt에 의해 차단됨"이면, 설정부터 고칩니다. 요청은 그 뒤입니다.

## 잘 안 될 때는 이렇게 말합니다

- "색인은 되는데 승인이 안 나."라고 하면 판정 사유와 글의 주제 분포를 함께 봅니다. 색인은 승인의 충분조건이 아닙니다.
- "승인은 났는데 광고가 안 보여."라고 하면 색인된 페이지에 광고 코드가 들어갔는지 확인합니다.
- "색인이 갑자기 줄었어."라고 하면 서버 오류, 도메인 변경, noindex 추가 여부를 확인합니다.

다음 절에서는 색인을 요청하는 화면 절차와 하루 한도를, 07-7에서 매일 밤 자동으로 돌리는 루틴을 다룹니다.
