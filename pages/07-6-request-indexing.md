# 07-6. URL 검사로 색인 요청하기

## 이 절에서 하는 일

사이트맵을 제출해 두면 구글이 알아서 읽는다고 생각하기 쉽지만, 새 글은 발견까지 시간이 걸립니다. 이 절에서는 주소 하나를 지정해 다시 읽어 달라고 요청하는 방법과, 그 요청에 걸린 하루 한도를 다룹니다. 한도가 작아서 무엇부터 누를지가 결과를 가릅니다.

## 사이트맵과 색인 요청은 하는 일이 다릅니다

| 수단 | 하는 일 | 범위 | 하루 한도 |
| --- | --- | --- | --- |
| 사이트맵 | 주소 목록을 알린다 | 사이트 전체 | 사실상 없음 |
| URL 검사 > 색인 생성 요청 | 그 주소를 다시 읽게 요청한다 | 한 주소씩 | 10건 안팎 |
| 내부 링크 | 새 글로 검색 로봇을 끌어들인다 | 자동 | 없음 |

사이트맵은 목록이고, 색인 요청은 개별 부탁입니다. 사이트맵에 있는 주소도 색인이 안 될 수 있고, 색인 요청을 눌러도 색인이 보장되지는 않습니다. 구글 도움말도 요청은 크롤링 대기열에 넣는 일이고 결과를 보장하지 않는다고 안내합니다.

## 화면에서 하는 순서

1. 서치콘솔 위쪽의 검색창에 주소를 붙여넣고 Enter를 누릅니다.
2. 검사 결과에서 현재 상태를 읽습니다. "URL이 Google에 등록됨"이면 이미 색인된 것입니다.
3. "색인 생성 요청"을 누릅니다. 이 버튼은 속성의 소유자나 전체 사용자에게만 보입니다.
4. "색인 생성 요청됨"이 표시되는지 확인합니다. 몇 분 걸릴 때가 있습니다.
5. 다음 날 같은 주소를 다시 검사해 "URL이 Google에 등록됨"으로 바뀌었는지 봅니다.

화면 문구는 판올림에 따라 조금씩 다릅니다. 버튼이 보이지 않으면 권한부터 확인합니다.

## 하루 한도

구글은 색인 요청의 정확한 한도를 공개하지 않습니다. 도움말에는 개별 URL 제출에 할당량이 있다는 설명만 있습니다. 운영자들이 보고하는 값은 하루 10건에서 12건 사이이고, 넘기면 "할당량 초과"가 뜹니다.

알아 둘 점이 네 가지 있습니다.

- 같은 주소를 다시 요청해도 더 빨리 읽히지 않습니다. 구글이 직접 그렇게 안내합니다.
- 한도가 소진되면 "할당량 초과" 대신 "문제가 발생했습니다"만 보일 때가 있습니다. 두세 번 연속 실패하면 한도가 찬 것으로 보고 그날은 멈춥니다.
- 한도가 자정에 초기화된다는 안내는 없습니다. 24시간이 지나야 다시 되는 사례가 많아, 매일 같은 시각에 도는 루틴과 잘 맞습니다.
- 한도가 속성 단위인지 계정 단위인지에 대한 보고가 갈립니다. 블로그가 여러 개라면 첫날 직접 재 보는 편이 빠릅니다. 한 블로그에서 요청을 채운 뒤 다른 블로그에서 한 건을 요청해 보면 됩니다.

## 무엇부터 요청할 것인가

| 순위 | 대상 | 이유 |
| --- | --- | --- |
| 1 | 그날 발행한 새 글 | 발견이 늦으면 첫 유입이 일주일 뒤로 밀린다 |
| 2 | 소개, 문의, 개인정보처리방침 | 애드센스 심사에서 보는 페이지 |
| 3 | 제목이나 본문을 고친 기존 글 | 다시 읽어야 수정이 반영된다 |
| 4 | 나머지 글 | 사이트맵과 내부 링크에 맡긴다 |

하루 10편씩 세 곳에 발행한다면 그날 새 글만 30편입니다. 전부 요청할 수 없으니, 새 글 중에서도 제목과 주제가 뚜렷한 것부터 고릅니다.

## 이렇게 말하면 됩니다

```
서치콘솔에 들어가서 내 블로그 속성별로 색인 상태를 확인해 줘.
- 사이트맵이 정상으로 읽히는지
- 색인이 안 된 주소 가운데 새 글과 필수 페이지를 골라 우선순위 목록으로 만들어 줘
목록 위에서부터 색인 생성 요청을 눌러 줘. 하루 한도에 걸리면 바로 멈추고,
어디까지 했는지와 남은 목록을 표로 남겨 줘. 이미 요청한 주소는 다시 누르지 마.
로그인이나 2단계 인증이 필요하면 카드로 알려 줘.
```

## 피클이 되묻는 것

| 피클의 질문 | 내가 고르는 답 |
| --- | --- |
| 어느 속성부터 할까요 | 애드센스를 신청한 곳, 그다음 발행량이 많은 곳 |
| 하루에 몇 건까지 할까요 | 10건, 할당량 초과가 뜨면 그보다 적게 |
| 이미 색인된 주소도 요청할까요 | 아니요, 색인 안 된 것만 |
| 실패한 주소는 어떻게 할까요 | 목록에 남겨 다음 날 다시 |

## 내가 승인하는 카드

색인 요청은 화면을 누르고 그 결과가 구글 쪽 기록에 남는 일입니다. 그래서 피클은 요청을 시작하기 전에 목록을 카드로 보여 줍니다.

| 카드에 보이는 것 | 내가 확인할 것 |
| --- | --- |
| 속성 이름과 주소 수 | 신청한 블로그가 맞는지 |
| 요청할 주소 목록 | 공개 글인지, 지울 글은 아닌지 |
| 예상 건수 | 한도 안인지 |

목록이 맞으면 승인하고, 빼려는 주소가 있으면 말해 다시 받습니다.

## 끝나면 보이는 것

| 시점 | 화면 |
| --- | --- |
| 요청 직후 | URL 검사에 "색인 생성 요청됨" |
| 몇 시간 뒤 | "발견됨" 또는 "크롤링됨" |
| 다음 날 이후 | "URL이 Google에 등록됨" |
| 이틀 뒤 | 페이지 보고서의 색인된 페이지 수가 늘어남 |

색인 수는 요청 건수만큼 늘지 않습니다. 요청은 읽어 달라는 부탁이고, 넣을지는 구글이 정합니다.

## 참고: API로 한 번에 요청할 수 없는 이유

한도를 피하려고 API를 찾게 됩니다. 결론부터 적으면 일반 블로그 글에는 쓸 수 없습니다.

| API | 할 수 있는 일 | 한도 |
| --- | --- | --- |
| URL Inspection API | 색인 여부와 사유 조회 | 사이트당 하루 2,000회, 분당 600회 |
| Indexing API | 색인 생성 요청 | 프로젝트당 하루 200건(기본값) |

URL Inspection API는 조회만 됩니다. Indexing API는 구인 공고와 라이브 방송 페이지에만 쓰도록 안내되어 있어, 일반 글에 쓰면 규정 밖입니다. 그래서 일반 블로그의 색인 요청은 화면에서 한 건씩 누르는 일로 남습니다. 이 반복을 매일 밤 정해진 시각에 돌리는 것이 07-7의 루틴입니다.

## 잘 안 될 때는 이렇게 말합니다

- "색인 생성 요청 버튼이 안 보여."라고 하면 속성 권한과 소유 확인 상태를 확인합니다.
- "할당량 초과가 떠."라고 하면 그날은 멈추고 남은 목록을 다음 날로 넘깁니다.
- "요청했는데 계속 색인이 안 돼."라고 하면 07-4의 사유 표를 보고 "크롤링됨 - 현재 색인이 생성되지 않음"인지 확인합니다. 이 사유는 내용을 고쳐야 줄어듭니다.
- "발견됨에서 넘어가지 않아."라고 하면 내부 링크와 사이트맵, 서버 응답 속도를 확인합니다.
